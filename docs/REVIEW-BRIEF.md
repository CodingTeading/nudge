## 2. 레슨 한 편의 구조 (POE 7블록)

모든 레슨이 같은 틀입니다. `lessons.json` 의 키가 그대로 블록입니다.

```jsonc
"atom-1": {
  "course": "atom",              // 소속 코스 id
  "sim": "build-an-atom",        // 쓰는 시뮬레이션 repo 이름
  "screens": "1",                // 특정 화면만 열기 (null 이면 전체)
  "mode": "solve",               // 수학 코스만. 있으면 ②가 '먼저 풀어 보기'
  "title": "...",                // 레슨 제목
  "lead": "...",                 // 제목 아래 한 줄
  "hook":    "① 이런 게 궁금하지 않나요",
  "predict": { "q": "② 먼저 예상해 보세요", "opts": ["A","B","C","D"] },
  "missions": [ "③ 실험으로 확인하세요 — 조작 지시 여러 개" ],
  "record":  "④ 본 것을 적어 두세요",
  "explain": { "right": 1, "body": "⑤ 이제 답을 맞춰 봅시다" },  // right = opts 인덱스(0부터)
  "real":    "⑥ 이건 어디에 쓰일까요",
  "quiz": [ { "q": "⑦ 확인 문제", "opts": [...], "right": 0 } ]
}
```

**설계 의도** — ②에서 답을 감추고, ③에서 직접 조작해 보게 하고, ⑤에서 대조합니다.
그래서 ②는 대부분 **흔한 오개념을 정답 옆에 오답으로 배치**해 두었습니다.

수학 코스(10·11·12·14)만 `"mode": "solve"` 라 ②가 "먼저 풀어 보기"입니다.
답이 정해진 문제를 짐작하라고 하면 어색하기 때문입니다.

## 3. 사용법 한 건의 구조

```jsonc
"build-an-atom": {
  "summary":  "이 실험이 무엇인지 두세 문장",
  "screens":  [ { "name": "화면 이름", "what": "무엇을 하는 화면인지" } ],
  "controls": [ { "name": "조작 도구 이름 (위치)", "desc": "무엇을 하는지", "tip": "요령" } ],
  "steps":    [ "이렇게 해 보세요 — 순서" ],
  "gotchas":  [ "헷갈리기 쉬운 것" ]
}
```

`_common` 키에는 모든 PhET 실험에 공통인 조작(집 버튼, 되돌리기 등)이 들어 있습니다.

## 4. 검증해 주셨으면 하는 것 — 우선순위 순

### ★★★ A. 사실 관계 오류

과학·수학적으로 **틀린 서술**입니다. 가장 중요합니다.

특히 살펴봐 주실 곳:

- **`explain.body`** — 설명이 길고 단정적이라 틀리면 피해가 큽니다.
- **`predict.opts` 와 `explain.right`** — 정답 인덱스가 실제로 맞는지.
  `right` 는 **0부터 세는 인덱스**입니다. `right: 1` 이면 두 번째 선택지가 정답입니다.
- **`quiz[].right`** — 같은 방식. 179문항 전부 확인이 필요합니다.
- **`real`** — 실생활 사례에 사실 오류가 섞이기 쉽습니다(수치, 연도, 원리).

특히 의심스러운 유형:

| 유형 | 예 |
|---|---|
| 수치 | 반감기, 온도, 파장, 각도, 이심률, 상수 |
| 인과 | "A 때문에 B" 가 실제로는 다른 원인인 경우 |
| 단정 | "언제나 / 절대 / 반드시" 로 쓴 것 중 예외가 있는 것 |
| 근사 | 교육용 단순화가 **틀린 개념을 심는** 수준인지 |
| 용어 | 한국 교육과정 용어와 어긋나는 표현 |

### ★★★ B. 미션이 실제로 작동하는가

`missions` 는 **화면을 보고 따라 하는 지시**입니다. 여기가 틀리면 학습자가 그 자리에서 막힙니다.

확인 방법: 해당 레슨을 열고(`lesson.html?l=<id>`) 시뮬레이션을 실제로 조작해 봅니다.

- 지시한 **조작 도구가 그 이름으로 그 자리에 있는지**
- 지시한 **화면에 그 기능이 있는지** (PhET 은 화면마다 도구가 다릅니다)
- 지시한 **결과가 실제로 일어나는지** (값, 색, 표시)
- 위치 표현("오른쪽 아래", "가운데 위")이 맞는지

> 이전에 이 유형의 오류가 여러 건 있었습니다. 예를 들어 분수 시뮬레이션에서
> 큰 분수가 "오른쪽 아래"에 있다고 썼는데 실제로는 **오른쪽 가운데**였습니다.
> 짐작으로 쓴 위치는 대부분 틀립니다.

### ★★ C. 퀴즈의 적절성

- 문항이 **레슨에서 다룬 내용**으로 풀 수 있는지 (밖에서 끌어온 지식 요구 금지)
- 오답이 **그럴듯한지** (너무 뻔하면 확인이 안 됩니다)
- 정답이 **하나뿐인지** (복수 정답 소지)
- ②와 ⑦이 **똑같은 것을 두 번 묻지** 않는지

### ★★ D. 난이도와 분량

- 대상은 **중학생~고등학생**입니다. 다만 운영자가 "**살짝 어려운 편이 좋다**"고 정했습니다.
  이 사이트를 찾아오는 아이들을 위한 것이라, 쉽게 만드는 방향의 지적은 필요 없습니다.
- 각 레슨에 `min`(분량, `courses.json` 의 레슨 목록에 있음)이 붙어 있습니다.
  미션 개수 대비 **실제로 그 시간에 되는지** 봐 주세요.
- 고등학교용 시뮬레이션을 중학생 코스에 넣은 곳이 있습니다
  (예: `models-of-the-hydrogen-atom`, `calculus-grapher`, `quantum-*`).
  **어느 선까지 다루고 어디서 멈췄는지**가 적절한지 봐 주세요.

### ★ E. 한국어 표현

- 어색한 문장, 오타
- 조사·띄어쓰기 (자동 검사를 걸어 뒀지만 놓친 것이 있을 수 있습니다)
- 중고등학생에게 설명 없이 던진 어려운 낱말

## 7. 결과를 이렇게 주세요

**JSON 한 덩어리**로 주시면 그대로 반영할 수 있습니다.
설명문 형태여도 되지만, 아래 필드가 다 들어 있어야 합니다.

```jsonc
[
  {
    "id": "atom-3",                  // 레슨 id 또는 시뮬레이션 repo 이름(사용법인 경우)
    "where": "explain.body",         // 정확한 위치. 배열이면 인덱스까지: "missions[4]", "quiz[1].opts[2]"
    "severity": "high",              // high(사실 오류·미션 불가) / medium(부정확·부적절) / low(표현)
    "kind": "fact",                  // fact / mission / quiz / difficulty / wording / crossref
    "quote": "정확히 이 문구가 문제입니다",   // 원문에서 그대로 복사 — 찾아 바꿀 때 씁니다
    "problem": "무엇이 왜 틀렸는지",
    "fix": "이렇게 고치면 됩니다",           // 대체 문구를 그대로 써 주시면 가장 좋습니다
    "confidence": "certain"          // certain / likely / unsure
  }
]
```

**`quote` 는 원문 그대로여야 합니다.** 찾아 바꾸기로 반영하기 때문에
줄임표나 의역이 섞이면 못 찾습니다. `<b>` 같은 태그도 그대로 두세요.

### 특히 이렇게 해 주시면 좋습니다

- **정답 인덱스 오류**는 `kind: "quiz"` 또는 `"fact"`, `where` 를 `explain.right` /
  `quiz[2].right` 로 찍고 `fix` 에 올바른 숫자를 적어 주세요.
- **미션 오류**는 가능하면 **실제로 열어 보고** 확인해 주세요.
  못 열어 봤으면 `confidence: "unsure"` 로 표시해 주세요.
- **문제 없는 곳은 보고하지 않아도 됩니다.** 전수 확인했다는 요약만 마지막에 한 줄 주세요.

### 검증 순서 제안

분량이 많으니 나눠서 주셔도 됩니다.

1. **정답 인덱스 전수 검사** (②61 + ⑦179 = 240문항) — 기계적이고 피해가 커서 1순위
2. **`explain.body` 사실 관계** — 61편
3. **`missions` 실제 작동** — 600개, 시뮬레이션을 열어야 해서 가장 오래 걸림
4. **`real` 실생활 사례의 수치·사실**
5. **사용법 61종** — `controls` 이름·위치, `gotchas`
6. **표현·난이도**
